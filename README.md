# Запись на приём к специалисту

ДЗ 1, вариант 3. Плохута Карина Дмитриевна, БИСТ-24-ПО-3. Префикс базы, схемы и Compose-проекта: `karina_plokhuta`.

Сервис показывает подходящие свободные слоты, бронирует время без пересечений, отменяет запись и считает загрузку специалистов и долю отмен. Есть список записей с фильтром и пагинацией, карточка со связанными сущностями, экран бронирования и сводка. Авторизация HTTP Basic; учётная запись `demo / demo`. Пароль хранится как PBKDF2-SHA256 с солью, 100 000 итераций.

## Требования

Испытано: Python 3.12.14, FastAPI 0.115.12, Uvicorn 0.34.2, Psycopg 3.2.9, PostgreSQL 16.15, macOS 26.6.2 arm64, Docker 29.7.2. Python-зависимости зафиксированы в `requirements-lock.txt`. Клиент: HTML, CSS, обычный JavaScript без сборки.

## Установка и запуск

Извлеките архив или клонируйте размещённый вами репозиторий, откройте его корень. Основной путь воспроизводит измеренный стенд: PostgreSQL в Docker, приложение в Python на хосте.

```sh
cp .env.example .env
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements-lock.txt
set -a
. ./.env
set +a
docker compose up -d db
python -m app.setup_db small
uvicorn app.main:app --host 127.0.0.1 --port "$APP_PORT"
```

Наполнение создаёт схему и таблицы. При повторе оно **удаляет указанную в DB_SCHEMA схему** и создаёт заново; записи этого сервиса будут потеряны. Рабочий объём: `python -m app.setup_db working`.

Полностью контейнерный запуск, на том же порту (остановите Uvicorn на хосте):

```sh
docker compose up -d --build
docker compose exec api python -m app.setup_db small
```

Результаты в `benchmarks/` сняты с приложением на хосте; серии с двух способов запуска смешивать нельзя. PostgreSQL зафиксирован по digest измеренной сборки. Остановка без удаления базы: `docker compose down`.

## Переменные окружения

| Имя | Назначение | Пример |
|---|---|---|
| DATABASE_URL | Подключение с хоста | postgresql://app:changeme@localhost:25433/karina_plokhuta |
| DB_SCHEMA | Схема PostgreSQL | karina_plokhuta |
| POSTGRES_PASSWORD | Пароль учебной базы в Compose | changeme |
| APP_PORT | Порт Uvicorn на хосте | 20803 |

Примеры — учебные значения; `.env` исключён из Git. Compose подключает API к `db:5432`, публикует порты только на 127.0.0.1.

## Проверка работоспособности

Откройте http://localhost:20803, войдите как `demo / demo`. В «Записаться» выберите услугу, найдите время и забронируйте слот. В карточке отмените запись: время вновь доступно. Проверьте «Мои записи» и «Сводка».

```sh
curl http://127.0.0.1:20803/health
curl -u demo:demo http://127.0.0.1:20803/api/appointments
python -m pytest -q
```

38 тестов: 6 тестов бизнес-расчётов и 32 проверки API/БД, включая одновременное бронирование, короткий слот, неверную услугу, отмену, 401/404/409/422, пагинацию и сводку. Перед каждым API-тестом автоматически пересоздаётся отдельная схема `karina_plokhuta_test`; тесты независимы от порядка. Нужна запущенная PostgreSQL, ручная подготовка не требуется.

Полный контракт: [CONTRACT.md](CONTRACT.md); параметры запросов и авторизация OpenAPI: [openapi.json](openapi.json). Документация после запуска: `/docs`. Девять бизнес-операций `/api` измерены; `/health`, `/`, `/static`, `/docs`, `/openapi.json` обслуживают запуск/интерфейс и в серию не включены.

## Данные и правила

Пять таблиц: accounts, services, specialists, slots, appointments. Специалист выполняет одну услугу; одна услуга есть у нескольких специалистов. Слот — отдельный час расписания. Услуги длятся 30, 45, 60 минут. Бронирование начинается в начале слота; остаток короткого приёма отдельно не предлагается. История отмен сохраняется. Интервалы полуоткрытые: соприкасающиеся записи допустимы, пересекающиеся запрещены. Бронирование/отмена блокируют строку специалиста до завершения транзакции.

Периоды — ISO 8601 с зоной. Слоты фильтруются по началу в [start,end); загрузка учитывает минуты пересечения с периодом. Доля отмен — среди записей, начало которых в периоде. Загрузка = занятые минуты / минуты расписания × 100; пустой знаменатель — 0. Генератор начинает расписание 01.10.2026 08:00 UTC, рабочий объём — 125 дней по 8 часов в сутки. Браузер показывает время в своей зоне. Для фиксированных учебных данных прошлые даты не запрещены.

Индексы — только пять первичных ключей (сохранены в JSON). Кеширование, очереди, фоновые задачи не применяются. Cache-Control: no-store, браузерные запросы cache: no-store. Сценарии не требуют пользовательских файлов.

## Повторение измерений

При работающем API из второго терминала с активированной средой и теми же переменными:

```sh
python -m benchmarks.measure small
python -m benchmarks.measure working
python -m benchmarks.reproduce
```

Каждая серия пересоздаёт основную схему, делает один прогревочный и 20 измеряемых запросов каждой операции, последовательно под `demo`. **Повторный запуск заменяет сохранённые JSON.** `small.json`/`working.json` содержат по 180 наблюдений, параметры, p50/p95/максимум, HTTP-коды, размер ответа, время обращения к БД, подключения и число запросов. p95 — элемент ceil(0.95*N) в отсортированном ряду. Чтения выполняются до записей. POST добавляет 21 строку с прогревом; отмена изменяет их. После серий 321 / 50 021 запись. Создание использует разные свободные слоты, чтобы измерять 201, а не конфликт 409.

X-Server-Ms — серверное время до готовности ответа. X-DB-Ms — сумма execute+fetch, включая драйвер и передачу из БД, вместе с запросом авторизации; X-Query-Count — число этих SQL-операторов. Подключение и commit/rollback измеряются отдельно, но входят в X-App-Ms = X-Server-Ms − X-DB-Ms. Это оценка доступа к БД со стороны приложения, не чистое время PostgreSQL. HTTP-время клиента включает получение тела; оно не используется как «код» при разложении. Загрузка страницы браузером отдельно не измеряется.

Условия: один процесс Uvicorn, PostgreSQL в Docker Desktop, один последовательный клиент, один прогрев, 20 повторов. Ранее запущенные контейнеры лабораторного портала оставались включёнными в обеих сериях. Это baseline, не нагрузочный тест ДЗ 2.

`reproducibility.json` подтверждает равенство количества и MD5 полного содержимого всех пяти таблиц после двух наполнений каждого объёма. Генератор не использует текущее время/случайность. `tests.txt` — фактический прогон. Снимки сделаны после рабочей серии, сводка содержит 50 021 строку.


## Результат повторной проверки

Исправлена зависимость теста пересечений от предыдущего теста: теперь он сам создаёт исходную запись, а каждый API-тест получает новое малое наполнение. Пройдены 38 тестов в прямом и обратном порядке, проблемный тест также запущен отдельно. Добавлены проверки чужой записи, точной загрузки на границе периода, короткого слота, неизменности даты повторной отмены, состава полей ответов и неверного тела POST. Журналы: `benchmarks/tests.txt`, `tests_reverse.txt`, `test_isolated.txt`.

`python -m benchmarks.verify` заново вычисляет статистики из 360 исходных наблюдений, проверяет HTTP-коды, число SQL и SHA-256 измеренных исходников. Результат: `benchmarks/audit.json`. Сервер, генератор и измеренные данные не изменены; исправление подготовки тестов не влияет на приведённые времена. Полный нормативный контракт ответов — `CONTRACT.md`; автоматически сгенерированный OpenAPI не описывает поля успешных ответов.
